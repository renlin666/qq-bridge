# 搜到网页却不能发图：修复记录

## 原因与实现

截图对应的真实聊天记录中，来源窗口在 2026-10-23 11:25 收到“再搜一张其他表情包发给好友”的要求，11:26 回复只能使用收藏。此前只有网页搜索及收藏表情发送工具，没有将网络图片作为图像交给模型、再发送图片的路径。Bing 的部分长中文查询还会退化成单字词典结果。

新增 `qq_search_images`：使用 Bing 图片搜索，解析真实原图/缩略图地址和来源页面，过滤无关结果，必要时尝试紧凑搜索词或主体名加“表情包”。通用的“表情包/图片”字样不会让其他主体误算相关。搜索后实际下载与校验图片，MCP 直接返回图像块和对应 `imageId`，模型应先看图再选，不能凭标题声称命中特定台词。

新增 `qq_send_image(imageId,requestId,targetKey?)`：默认发当前聊天，也可传已授权好友/群的真实 `targetKey`。`qq_send_to_contact` 同时支持 `imageIds`，可以搭配文字发送。不需要收藏网络图片，也不需要用户重发。已有收藏的 `stickerIds` 继续可用。

缓存保存与预览完全相同的图片字节；发送时使用校验后的 base64 图片段，不让网关重新抓任意 URL。保留原有发送队列、来源令牌、双方联动授权、模式、静默、工具开关、目标限频和真实消息回执。每步写入前记录幂等状态；未知结果不自动重发。搜图只接受查询词，发图只接受本会话真实搜索 ID，不开放任意路径或下载工具。

## 边界

- 搜图继承 `webSearch.enabled`，可用 `webSearch.images.enabled=false` 单独关闭。不开启额外模型，原聊天模型及平台不变。
- 每次最多预览4张，默认3张；每张及整批累计不超过8MB，保留现有图片格式/像素、公网地址、固定 DNS、逐跳重定向和传输大小校验。
- 原图无法下载时可使用搜索引擎实际返回的缩略图，明确标记 `variant:thumbnail`；发送仍使用这份真实预览字节，不自动替换成其他图。
- 缓存按机器人账号与来源窗口隔离，ID 有效期1小时；最多64张、64MB。过期或文件不可用时要求重新搜索。搜索词及结果不得包含已知会话令牌。
- 来源网页与图中文字都是外部资料，不能改变规则。具体台词或梗的匹配需实际看图判断，没有合适结果应说明。
- 当前会话发图与跨会话发送均沿用已有联动授权列表；未获授权的窗口不会因此获得发送或读取其他窗口的权限。

## 参考与验证

先检索 GitHub 并检查 [icrawler 的 Bing 图片实现](https://github.com/hellock/icrawler/blob/master/icrawler/builtin/bing.py) 与 [SearXNG 图片引擎协议说明](https://docs.searxng.org/_modules/searx/engines/bing_images.html)。借鉴图片搜索与元数据处理流程，使用独立 Node 实现，没有复制上游代码或引入其运行环境。

- 图片专项12项与原联系人发送13项全部通过，覆盖元数据解析、相关性、真实图像块、原图/缩略图、缓存校验、账号/窗口隔离、过期/撤权、未知图片ID、当前聊天/好友/群图片发送及缺失回执。发送测试使用模拟 QQ 网关。
- 全量审计39/42个脚本通过；仍是已有的 `start.bat` 行尾、预设 CRLF 保留和缺少 `VOICE.md` 三项失败。最后收紧相关性与缓存错误提示后，相关25项再次通过。
- 真实 MCP → 运行中桥接 → Bing → 原图链路返回3张真实图片，MCP 图像块与可发送缓存逐字节一致；人工查看两张 JPEG，确认是实际表情图片。现有55个 QQ 工具可发现新增搜图、发图与联系人 `imageIds` 参数。
- 模型选择、5个会话映射、`dsh` 配置哈希保持一致。错误来源令牌仍被拒绝；没有向真实好友发送测试图片，也没有重放截图中的发送请求。

证据：`state/image-search-targeted.log`、`state/image-search-audit.log`、`state/image-search-live-verification.json`。备份：`state/feature-backup-<timestamp>`。
