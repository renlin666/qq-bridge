# 视频标题与观看规则（0.3.0-rc.5）

## 当前规则

用户调整了 rc.4 的限制：无需 @，视频卡片标题、链接和编号正常显示，也按原会话唤醒规则处理。消息标记为 `videoWatch: {status: 'not-read', evidence: 'share-metadata-only'}`，允许按标题接话，不能把标题当作已观看的证据。

真正观看 B站视频仍经 `qq_read_bilibili`：整段确认不超过 180 秒，或取得 `bilibili.approvalUserId` 配置的真实 QQ 账号对该条视频的明确许可。许可账号只存本地私有配置，不写进公开源码。默认 8 帧；多 P 总时长、截片参数、缓存与省略 @ 不能替代时长检查或许可。

许可账号在同一会话回复原视频 `允许观看视频`，或发送 `允许观看视频 734`（734 为视频消息的本地 seq，也接受真实 messageId）。读取工具可自动查找当前会话保留的许可消息，也可通过 `approvalMessageId` 指定。工具校验实际发信人、原文和目标消息，引用/转述他人许可、昵称、模型传入批准布尔值都不算许可。许可不能跨会话或自动用于下一条视频；许可消息移出保留范围、账号配置改变后须重新授权。

许可允许超出 3 分钟，但不解除媒体格式、下载大小、超时及会话白名单限制。若平台根本没有提供可用时长，当前抽帧流程仍无法定位画面，将明确返回 `duration_unknown`；不会把标题或空结果冒充观看。

原始本地消息、记忆和人物关系保留。更新后重启桥接并刷新 QQ MCP stdio 进程。备份位置在本地 `state/backups/rc5-backup-locations.json`，备份含私有数据，不上传 GitHub。本次无数据库迁移，回退优先只回退源码，保留较新的记忆。

验证包含消息视图、真实入线、无 @ 短视频、超长/多 P 拒绝、指定账号对单条视频授权、非许可账号/转述拒绝、配置变更及伪造参数拒绝。离线测试不发送 QQ 消息，不启动真实模型回合。

## rc.4 历史排查

本次排查的未 @ 分享没有对应的 `qq_read_bilibili` 调用。旧规则只限制视频读取工具，但 QQ 卡片标题会转换成消息文字并进入模型，因此模型仍会按标题接话，表现为未经要求就“看视频”。这项证据仅对应本次查到的消息，不能据此断言所有历史视频都未读取。

rc.4 曾将未 @ 视频标记为 `mention_required`、隐藏卡片标题，并禁止单独分享唤醒；这组规则已由上述当前规则替代。

旧消息快照、未读/近期列表、等待结果和单条消息详情同样恢复元数据展示。模型仍须拿到实际画面或字幕后才能描述相应视频内容。

验证：`npm test`（149 项）、`npm run test:audit`、`npm run test:mcp-servers`、`npm run release:check`。测试不发送真实 QQ 消息，不启动真实模型回合；离线回归不能代替群内长期行为观察。

更新运行中的桥接后，应同时刷新 `mcp-snowluma-safe.js` 的 stdio 进程，以装载新的模型消息视图。保留当前配置和 SQLite 数据，不通过清空状态或重建人物画像更新。

更新前后在本地 `state/backups/` 保存源码归档、Git bundle、配置/会话快照及 SQLite 在线备份，位置由 `rc4-backup-locations.json` 记录。备份含私有数据，不上传 GitHub。需回退时停止桥接，使用 `v0.3.0-rc.3` 源码及更新前快照；优先保留较新的记忆数据，因为本次没有数据库结构迁移。
