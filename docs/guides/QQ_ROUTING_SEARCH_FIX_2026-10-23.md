# 跨窗口令牌与联网搜索修复

## 已确认的问题

截图对应的工具日志显示：私聊窗口调用了 `qq_get_recent_messages(key=群聊key)`，同时携带私聊令牌，返回 `agent token 无效`。该轮没有调用已实现的 `qq_handoff`。因此是模型选错跨窗口调用方式，不是 QQ 账号无法进群。

原联系人入口只能列出授权 key，缺少好友昵称/备注查询。只读检查确认截图提及的好友确实已在好友列表和私聊白名单内。

联网搜索此前确实关闭：`webSearch.enabled=false`。这是本地工具配置，与聊天模型是否能调用外部工具是两件事。

## 修改与启用

- 新增 `qq_find_contact`，按昵称、好友备注、群名、QQ 号查询现有授权目标；`qq_list_linked_conversations` 同时显示名称。查询不暴露全部好友或其他窗口令牌，近似匹配明确标记候选，不自动发送。
- `qq_handoff` 的 schema、工具说明和每轮提示明确区分来源 `key/token` 与目标 `targetKey`。目标窗口由桥接主动唤醒，无需先在群里 @。
- 交接可携带最多 3 个真实 `stickerIds`。源窗口先收藏当前图片，接收窗口使用自己的令牌发送。仍不允许私聊令牌直接读取/发送群聊。
- 普通读取工具遇到令牌不匹配时，错误信息提示联系人查询与交接的正确方式。旧只读工具描述也明确其模式限制。
- `prompt/unread/recent/wait` 返回当前能力说明，让已在等待中的旧回合也能发现新工具和搜索状态，减少继续沿用“只能先@”“搜索关闭”等旧结论。
- 已启用独立 Bing 搜索：`webSearch.enabled=true`、`provider=bing`。聊天模型、模型平台、模型凭据与 5 个现存会话的模型选择保持不变；搜索不调用额外 LLM。
- 修复中文多词搜索可能退化为无关单字结果的问题：过滤明显不相关结果，必要时对主关键词精确重试一次。

桥接已重载，QQ MCP 与搜索 MCP 已重新连接；5 个现存会话映射保留。

## 验证

- 新路由/搜索回归 5 项和原社交回归 15 项通过；原搜索/媒体检查通过。
- 全量审计 37/40 个脚本通过。其余仍是原有的 `start.bat` 行尾、提示词 CRLF 保留、缺少 `VOICE.md` 三项问题。
- 真实 MCP 只读检查：50 个 QQ 工具可发现；私聊令牌读取群聊继续被拒绝，但错误信息指向正确交接方式；可按备注查到授权好友；当前回合能力说明显示交接和 Bing 搜索已启用。
- 真实搜索返回 8 条结果，含与查询主体相关的标题和链接。
- 修改前后 5 个会话的模型选择和会话映射一致；`dsh` 配置哈希一致。
- 本轮没有向好友或群发送测试消息，没有自动执行截图里的转图请求。图片交接和目标唤醒使用临时状态及模拟 QQ 接口验证。
