# QQ 每条回复费用预算

`config.json` 的 `costControl`：

```json
{"enabled":true,"maxCnyPerMessage":0.1,"cacheHitRatio":0.9,"exemptOwner":true}
```

启用后运行 `node scripts/setup-cost-guard.mjs <DSH profile>`，在该 profile 的 patch
安装 `qq-cost-guard`。确认 `state/cost-guard-status.json` 的 PID 为当前 DSH 进程且
`enabled=true`，才算运行中生效；没有热加载的安装需重启 DSH。

预算单位是**成功发出一条 QQ 回复**：发送前的多次模型调用、工具查询后继续生成都
累计计入本条。网关返回有效消息编号后，下一次模型请求开始使用下一条回复的预算，
即使两条回复属于同一个 DSH 回合。模型内部文字、等待、失败或未知发送结果不清零。
文本、图片、表情、语音均以实际发送回执为界；跨会话发送计入发起任务的来源会话。
控制命令的系统回执不算 AI 回复。并发旧请求晚到的 usage 不会冲抵下一条回复的预算。

新处理任务开始新预算；输出截断后的自动续写，在尚未发出回复时沿用余额。
旧配置 `maxCnyPerTurn` 可兼容读取，但优先使用 `maxCnyPerMessage`。黑话学习会话
没有 QQ 发送动作，仍按处理回合控制；其他 DSH 聊天不受影响。

`exemptOwner` 默认关闭。开启后，配置中的 `ownerQQ` 私聊，以及由其真实消息发起的
当轮任务，可以超过 ¥0.10；单次输出上限仍为 2048 token，费用照常记录到账单。
二代群聊只认本次未读快照中的管理员本人消息，不认历史消息、引用里的 QQ 号或
模型自行声称的许可。桥接通过本地一次性授权记录关联具体投递，自动续写沿用授权，
下一轮普通消息恢复预算限制。预算拦截的技术错误只写后台，不向 QQ 发送。

正常回复单次输出最多 2048 token。调用前按当前官方 Flash 单价、90% 输入缓存命中
假设、完整消息/工具声明/工具历史的 UTF-8 保守上界和最大输出预留；预留后余额不足
便阻止请求。图像按官方每图最多1024 token计入，文件句柄计入文本投影余量。
拦截线直接使用配置目标，不额外扣除 ¥0.001 缓冲；例如合计估算 ¥0.0991 可放行。
这可能使较长上下文或看图请求提前停止；不会删除历史或自动重置会话。

收到真实 usage 后按未命中、命中、缓存写入、输出分别结算；失败或没有 usage 的请求
保留预留。并发请求先占款，插件重载也保留账本。日志和
`state/cost-guard-last-block.json` 记录停止原因；`state/cost-budgets.json` 是预算状态，
`state/cost-deliveries/` 保存真实发送的会话回执。预算清零不删除或修改 token 账单。

**这是按缓存假设运行的估算控制，不是人民币硬上限。** 服务端决定实际命中率，
实际命中不足、计费口径变化时单次调用可能超过目标；已发生费用不能撤销，后续调用
会停止。单价使用本项目官方价目表，当前仅放行已确认的 QQ Flash 模型。

验证：`npm run test:cost`。测试全部使用临时文件和模拟模型流，不发 QQ 消息或付费请求。
