# 关系阶段设计建议

日期：2026-10-24。状态：研究方案，未修改长期评分、阶段阈值或现有数据。

## 当前状态

rc.6 已接入具体相处指导、当前会话内的临时反应，以及最多三位最近说话人的独立提示。实际阶段判断仍主要使用亲近、熟悉、信任的加权分数；原有边界维度没有参与该总分。更细致的关系组合和相处偏好尚未实现。

此前生产库没有互动事件；保留日志没有关系事件工具调用，摘要工具调用不等于关系更新。这次已补触发指导并验证写入链路，但持续落库情况仍需真实对话验证。不能靠新增阶段掩盖写入未发生的问题，也不回填虚构历史。

## 查到的实现参考

1. [Monika After Story 的好感模块源码](https://github.com/Monika-After-Story/MonikaModDev/blob/master/Monika%20After%20Story/game/script-affection.rpy)：按阶段触发事件，并对增益设置日上限。可借鉴阶段与具体行为联动；其中恋爱剧情、离线惩罚不直接移植到群聊。
2. [AstrBot Favour Ultra 说明](https://github.com/nuomicici/astrbot_plugin_Favour_Ultra/blob/main/README.md)及[回复处理代码](https://github.com/nuomicici/astrbot_plugin_Favour_Ultra/blob/main/main.py)：阶段描述注入上下文，回复后的钩子解析关系变化并更新数据。可借鉴正常回复与关系写入衔接；不直接照搬明文标签协议、自动拒回或全局共享模式。
3. [Humanoid Agents](https://github.com/HumanoidAgents/HumanoidAgents)及[作者论文](https://arxiv.org/abs/2310.05418)：将情绪与关系亲近度作为不同因素影响对话和行为。可借鉴不同时间尺度的状态，而无需引入完整的模拟城镇。
4. [Generative Agents 作者论文](https://arxiv.org/abs/2304.03442)：将观察记忆、检索、反思和计划结合。支持用有依据的共同经历影响行为的思路，不能据此证明本项目某个档位数最优。

这些是机制参考，未进行依赖、许可证兼容性或完整安全审计，不建议直接安装替换。本方案是结合现有项目的设计判断，不是经过统一实验验证的最优标准。

## 五个长期阶段

保留五档，改为描述关系进展。各阶段的反驳权、自主判断和拒绝都保留；区别在于熟悉程度、话题深度和相处自然程度。

| 阶段 | 判断依据 | 具体行为 |
| --- | --- | --- |
| 初识 | 尚无稳定、可靠的互动依据 | 可接公开的梗，不装熟，不编经历 |
| 认识 | 已确认基本信息或兴趣，有过可辨识的交流 | 自然接续话题，适度反问和轻微调侃 |
| 熟络 | 多次有效互动，了解部分说话习惯 | 推进梗、补细节、自然吐槽；互损仍看本人偏好 |
| 亲近 | 亲近与信任都有实质互动支持 | 主动关心相关进展、直说不同意，能嘴硬也能缓和 |
| 深交 | 稳定的信任、熟悉与亲近，有不同来源的持续证据 | 减少客套，理解共同梗和个人边界；有误会也能自然修复 |

不靠消息数量单独升级，不因刷问候、夸奖或模型自报分数升级。保留现有日限额、事件去重和升降档缓冲；具体门槛需用真实案例校准，当前不预设一组未经验证的“最佳数字”。

## 阶段以外的两层信息

### 人物相处偏好

保留亲近、熟悉、信任、边界尊重四个独立量。增加一个小型的玩笑偏好字段：未知、轻度玩笑、互损舒适、明确叫停。它属于有证据的相处偏好，不等于好感分数。

同样的亲近阶段，可以分别是互损型朋友、认真型朋友、游戏搭子等。标签必须来自已知兴趣、自述和互动反馈；推测保留置信度，不当成已确认画像。不能因为群里别人喜欢损就给某人套上同样偏好。

熟悉度高而信任低，应能表达“认识很久但保持距离”；亲近和信任高、却不喜欢互损，也应自然亲近而不挖苦。加权总分不能把这些区别抹平。

### 独立的情绪与矛盾状态

玩闹、不耐烦、认真、缓和继续是短时状态。“戒备、疏远、修复中”也应独立于长期阶段，避免一次生气就变成陌生人。

真实冲突还可以保留一个有来源的未解决事项，而不是只靠固定计时器忘掉。道歉可以先让语气缓和，但不自动恢复全部信任；对方明确停止玩笑后应立即收住。高好感不是更容易生气，更不意味着必须一直迁就。

管理员设置的高档位保底继续作为显式待遇规则保留，不伪造分数、经历或互损许可。迁移旧“戒备”不能简单改名为“初识”，须保留原维度和有据冲突信息。

## 回复如何体现区别

在双方明确处于游戏玩笑语境、对方接受互损时，“你又菜了”可以接成“那你下把带我，光会点评可不算本事。”这是示例，不是固定回复模板，也不是来自真实聊天。

对不喜欢互损的人，可以接“下把你来，我看看教学局。”对方说“我认真的，别闹”时，无论多高档位都转为认真。若同一梗反复造成不适，可表达不悦并收住，不需要随机发怒或升级为辱骂。

## 可靠写入与成本

建议下一步把结构化事件与正常回复流程衔接，减少额外调用独立关系工具的依赖。例如在现有发送动作中携带可选事件元数据，由宿主验证真实来源、人物、证据、幂等和幅度，返回 applied/ignored 及原因；数字仍由宿主规则决定，用户文本里的标签不能直接控制分数。

复用当前聊天回合的判断，普通中性聊天不必加分或记事件；不增加逐条独立的付费分类请求。只注入当前人物的阶段、相处偏好、临时状态和相关关键词，正文按需读取。成本变化要实际测量，不能预先宣称固定比例的 token 节省。

建议顺序：先核验真实事件写入与回执，再用回放案例校准阶段和偏好，最后按真实反馈调整门槛。先做行为映射，避免先扩成十几个空洞档位。

## 验证标准

- 同一段话对不同人物有合理差别，但事实判断不因好感改变。
- 公开接梗、熟人互损、真正冒犯、引用别人的话能区分处理。
- 高档位在明确叫停后停止玩笑；和解不会篡改过去的事件。
- 阶段变化有真实来源与可解释回执，中性聊天不被强行计分。
- 保留机器人、人物、群聊/私聊隔离，不能用群里资料读取私聊正文。
- 对比旧版与候选版的虚构场景回放，人工评价接梗自然度、情绪连贯性和人物区分；不能只用测试数量证明“更像真人”。
