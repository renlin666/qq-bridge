# 关系阶段、偏好与事件回执

正式插件采用五个长期相处阶段，数字维度仍独立保存。阶段控制熟络程度，不代表互损许可，也不影响事实判断。

| 阶段 | 初始晋级条件 | 主要表达区别 |
| --- | --- | --- |
| 初识 | 新人物且没有已应用关系事件 | 可以接公开梗，不编共同经历 |
| 认识 | 至少一条已应用事件 | 接已确认的兴趣线索，补细节、自然追问 |
| 熟络 | 5 条实质正向事件、跨 2 个 UTC 日期、熟悉度 ≥40 | 主动沿梗多演一步，补反转 |
| 亲近 | 15 条、跨 5 个日期、至少 2 类；熟悉/亲近/信任 ≥55，边界尊重 ≥50 | 主动接话、嘴硬、有分歧直说 |
| 深交 | 40 条、跨 14 个日期、至少 3 类；熟悉/亲近/信任 ≥75，边界尊重 ≥70 | 有已证实的共同经历才接旧梗，也会抛新梗 |

这是首版可校准的工程门槛，并非心理学量表。实质正向事件包括 positive_chat、shared_activity、support、deep_talk；普通中性聊天不必评分。原有冷却、日限额、重复收益递减继续生效。遗忘后撤销的事件不再作为晋级依据。降档维度阈值留 3 点迟滞，避免临界值附近反复切换；证据被撤销则不享受该宽限。

原型库默认保留原 API 行为；正式插件显式启用 `relationshipStages: true`。迁移事务只增加 `relationship_stage_origins` 和 `relationship_stage_state` 表，保留原来的维度、旧 tier、事件和账本。已经建立的熟悉关系保留迁移依据，长期不活跃仍至少视为认识；信任不足时不会因此保留亲近待遇。旧“戒备”单独保留谨慎标记。基础 schema 仍为 v2，旧版可以打开这些数据库。管理员的最低档位是独立待遇规则，不改自然阶段和分数，不授权互损，也不消除隔阂。

## 偏好与矛盾

每个机器人、会话和真实人物独立保存玩笑偏好：unknown、light、mutual、stop。首次使用统一默认 unknown。3 条不同来源的玩闹观察只产生未确认的 light 倾向；不能据此获得 mutual 权限。本人明确说“我可以接受互损”等才确认 mutual；“别再拿我开玩笑了”等明确叫停在真实入线时即可保存，不依赖模型另调工具。引用、假设和疑问句不直接确认；识别范围刻意较窄，含糊说法应澄清。

冲突和越界分别留下 guarded/distant；道歉转为 repairing，不自动恢复信任。resolve_conflict 需要本人明确翻篇或和好，保留过去的事件。旧消息不能覆盖更新偏好或解除更新的隔阂。偏好、隔阂保存到私有 `social-policy.db`，具有持久去重审计；临时情绪继续保存在 `reactions.json`，到期衰减。明确叫停、认真状态或未解隔阂会移除当前玩闹指引，避免同时注入相反要求。关系、偏好和当前情绪均不跨人串用；情绪与偏好还不跨会话。

## 正常回复附带事件

`qq_send_message` 必须提供 `socialEvents`，没有变化时传 `[]`，最多 3 项。例如下面是虚构测试消息，不能用于回填真实关系：

```json
{
  "messages": "谢谢，你这么说我就有底了",
  "socialEvents": [{"messageId":"fixture-1","kind":"support","evidence":"我来帮你解决这件事"}]
}
```

人物、机器人和会话由原消息决定，元数据不能传身份或分数。宿主先校验结构，全部 QQ 发送获得有效消息编号后再记关系；返回 applied、ignored、duplicate、rejected 或 skipped 回执。缺少编号、发送失败或部分失败时跳过附带事件。事件拒绝不会把已发 QQ 误报为失败，不能为补记事件重发 QQ；需要补记时仍可使用 `qq_social_relationship_event`，同一来源继续受去重约束。HTTP 接口兼容省略该字段的旧调用，并以 `socialDecisionProvided=false` 标出。

复用当前聊天回合，不新增逐条付费分类。每次唤醒仍最多携带 3 位人物、总计 1500 字符，主要人物才携带相关记忆关键词，正文按需读取。没有量化 token 节省比例，需实际账单对比。

## 验证与回退

回归测试使用虚构人物和假 OneBot 回执，覆盖阶段、迁移、旧版本读取、偏好确认与推测、叫停、矛盾修复、证据/撤权、实际发送 API、重复、失败/部分成功及无编号回执。生产数据迁移先用 SQLite 在线只读快照验证，不向真实库写测试事件，也不触发 QQ 发送或付费模型回合。自动测试能证明约束和数据流；自然接梗的质量仍需后续真实使用反馈。

备份包括源码 ZIP、Git bundle、配置、会话、3 个原 SQLite 库、存在时的 social-policy.db 和 reactions.json，并保存哈希清单。回退先停桥接，再回退源码；优先保留最新记忆库，新状态由旧版忽略。需要恢复数据时先另存当前数据，再恢复一致快照，避免丢失升级后的互动。更新后需要重启桥接并刷新 QQ MCP stdio 进程。
