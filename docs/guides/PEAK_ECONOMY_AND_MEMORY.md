# 峰谷节流与本地记忆索引

版本：0.3.0-rc.3，2026-10-24。

## 峰时少聊、谷时按原设置

控制台 → 二代仿真 →「峰谷节流」。保存后即时生效；代码升级本身需要重启桥接。

```json
{
  "socialV2": {
    "peakEconomy": {
      "enabled": true,
      "mode": "auto",
      "probability": 0.2,
      "minIntervalMs": 900000,
      "replyChars": 80
    }
  }
}
```

`auto` 使用 `pricing` 价目表的北京时间判定；当前官方规定工作日（不含中国法定节假日）09:00–12:00、14:00–18:00 为高峰，其余为谷时。见 [DeepSeek 官方价格](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)。如果走中转平台并采用不同计价，可以选择 `peak` 强制节流或 `off` 强制谷时；项目不会声称能够读取供应商实时账单。假期表和价目规则沿用项目本地维护的数据。

峰时在原唤醒条件满足后，再决定是否发起模型请求：默认保留 20% 可选唤醒，每群至少间隔 15 分钟。这里限制的是模型唤醒，不能等同于实际发言数或计费节省率。80 字是给模型的闲聊建议，不硬截断完整答案。

私聊、@/引用机器人、拍一拍、首次初始化与手动唤醒保留。即使会话设置了 anyMessage，原消息的真实 @ 证据仍能豁免。谷时不追加节流，继续使用原有唤醒、发送和白名单规则；不会自动提高原配置的主动概率，也不会变成无限发言。

后台会在真正投递时检查时段，离线队列不会携带旧的谷时许可越过峰时限制。跳过的消息保留为未读，不调用模型；有限睡眠延期检查，至少间隔一分钟，避免忙循环。成功唤醒间隔记录写入会话状态，重启后继续执行。

## 旧资料也改用关键词入口

此前旧话题和人物印象已经保存在 `state/social-v2.json`，共享摘要保存在 `state/shared-memory.json`。0.3.0-rc.2 启用了新库，但没有批量归档这些旧资料，入口仍可能直接附带最多 1200 字旧摘要。本版本修正该行为。

启用 social-memory 后，旧话题、仍有效的想法、昵称人物印象及当前获准的共享摘要会归档到 `state/extensions/social-memory/legacy-memory.db`，保留原文件。后台每分钟同步允许会话，查询和读取前也检查当前源记录。归档以原会话和机器人账号隔离，不将昵称猜成 QQ 号；`identityBound: false` 表示旧资料尚未经真人身份重新核实。

唤醒和 `qq_get_prompt` 不再直接注入旧摘要，自动注入只提供与当前消息相关的少量关键词与编号。`qq_social_memory_query` 返回索引；`qq_social_memory_read` 按编号取正文；没有关键词命中时不塞无关资料。检索采用本地分词/词项重合，不调用额外模型，不是向量语义检索。

原始来源删除、想法过期、会话或共享权限撤销后，旧编号不能继续读取。旧条目要用原 `qq_memory_remove` / `qq_shared_memory_remove` 删除来源；新 `qq_social_memory_forget` 会明确提示这一点。现有显式旧记忆查询工具仍可按需读正文。新确认事实仍写入 `memory.db`，关键词元数据位于 `keyword-index.db`。

这些都是项目自己的持久库与受限工具，没有写入 DSH 全局原生 meow-memory 数据库。

## 个别人固定在最高两档

本机私有配置支持 `extensions.social-memory.config.minimumTiers`：键为真实 QQ 账号，值为 `亲近` 或 `深交`。指定 `亲近` 后，该人物的生效相处档位不会低于亲近，仍可提升到深交；群内只得到相处提示，不暴露私人分数。

这是操作者显式设定的档位保底，不伪造成历史好感加分或真实互动。原始分数与事件账本仍保留，负面事件照常记录；未配置的其他人物继续独立变化。规则不会自动授予建档白名单权限，私人账号列表不得发布到 GitHub。

## 验证与回退

测试覆盖峰谷边界、节假日、强制模式、排队跨时段、直接 @、私聊、有限睡眠、设置权限、间隔持久化、旧资料按需读取/删除/跨群隔离，以及指定人物档位保底。

本轮本机验证：147/147 项测试、48/48 个全项目审计脚本、24/24 项浏览器界面检查全部通过，含峰谷表单保存和移动端排版。三个 MCP stdio 握手通过；依赖审计 0 项已知漏洞，发布扫描通过。生产检查确认 DSH 与 QQ 网关正常、旧资料归档 52 条，检查 6 个会话的 get_prompt 均未直接注入旧摘要全文。没有向联系人发送测试消息，实际账单节省仍需后续测量。

部署前备份源码、Git 历史、配置及关键状态，SQLite 用在线备份接口保存一致快照；保留 v0.3.0-rc.2 标签。故障可先关闭 peakEconomy，或在独立目录恢复旧标签。回退前保存新增资料，不清空 state，不全量覆盖新聊天与发送账本。旧记忆原文件一直保留。
