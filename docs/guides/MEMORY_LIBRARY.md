# 新旧记忆与资料库

旧资料继续保留。新库按真实 QQ、机器人账号、会话和来源消息保存，不凭昵称推断身份。

| 资料 | 用途 | 进入回复的规则 |
| --- | --- | --- |
| 旧话题、旧昵称印象、旧共享摘要 | 历史线索与原文档案 | 关键词检索、正文按需读取；未经重新核实 |
| 自动采集的本人明确原话 | 偏好、学习项目、使用习惯 | 保留原消息编号与原话，已确认指“本人明确说过”，不代表外部查证 |
| 缺少原消息证据的旧印象整理 | 待核实候选 | 不进入已确认事实检索；面板可查看并追溯旧记录 |
| 关系、玩笑偏好、隔阂 | 相处方式 | 独立计算，记忆回填不增加关系分数，不重放历史玩笑偏好 |

确认的迁移记录优先检索，已迁移的旧索引不重复返回；遗忘迁移记录后也不会借旧索引复活。旧原文仍可由管理员在“旧印象 / 摘要”中查看。

自动建档范围可设为白名单群中实际发言的人，以及私聊白名单人物。读取与写入仍限于原会话；群友不会因此自动取得私聊权限。

自动提取使用保守规则，不调用额外模型：只保存有逐字证据的明确本人陈述。转述、假设、玩笑、不确定、敏感、截断内容和临时位置不作为自动事实。复杂事件由模型使用 `qq_social_memory_remember` 补记，绑定当前会话真实 `messageId`。

## 查看与诊断

桌面“云端机器人管理面板”→“记忆库”。支持关键词、人物、会话、类型和确认状态筛选，展开可见来源；“采集记录与历史回填”显示跳过、重复和保存原因。

数据位于服务器 `state/extensions/social-memory/`：`memory.db`、`keyword-index.db`、`legacy-memory.db`、`social-policy.db`、`capture.db`。面板经已有 SSH 隧道读取管理员专用只读接口；不向 agent 开放整库。

## 手机人工核实与关系查看

安卓面板 1.1.0 的“记忆 → 待核实”支持确认属实、纠正并确认、驳回。仅当前白名单会话、当前机器人、可建档人物且未过期的结构化候选可提交。未绑定真实人物的旧原文继续只读。桌面界面保持原有功能。

`POST /api/memory-library/review` 使用控制台认证，拒绝 agent 头；请求只接受 memoryId、action、expectedVersion、requestId、content、note。人物、会话、机器人和核实管理员身份由服务器确定。版本冲突返回 409，同一编号与同一正文重试去重。不要通过此接口传入分数、身份或会话。

正文、旧版本、核实前后内容和审计记录在同一事务内保存，审计失败则全部回滚。确认 / 纠正后同步已确认索引；驳回后抑制旧索引再次出现。原文、证据及决定保留于管理员查看范围。模型读取已核实记忆时获得 verification.method=administrator_review，避免把人工确认描述为人物原话。

“关系”读取 `GET /api/relationships`：综合分、四项维度、已保存关系阶段、现有最低阶段、互动证据及最近变化账本。玩笑偏好、隔阂和临时反应另列。无关系记录的人物显示“尚无评分”，不补零分。此接口没有写入操作，也不调用会执行维护衰减的 getRelationship。人工核实本身不记互动、不加减分、不重算阶段。

回归：`node --test scripts/test-phone-memory.mjs scripts/test-memory-capture.mjs`。成功核实使用隔离临时数据库；生产环境检查仅提交无效 / 过期版本，不替管理员作核实决定。

历史回填先从当前白名单会话的原消息快照和工具读取结果收集证据，再用 `scripts/backfill-social-memory.mjs` 预览，显式 `--apply` 执行。只在桥接停止、已完成 SQLite 一致性备份的维护期间运行；完成后以 qqbot 身份启动服务。重复执行不会重复增加记忆。
