# 0.3.0-rc.2 本地记忆、视频门槛与备份

日期：2026-10-24。这是 QQ Bridge 自身的内置功能插件，不需要向 DSH 安装新的功能包。

## 视频与提示词消耗

- B站工具只处理当前会话原消息中真实 `at` 段指向机器人的分享。昵称、文本写“@”、引用回复和 @全体均不算；私聊同样执行此条件。旧消息没有可核实的 @ 证据时拒绝读取。
- 默认总时长上限 180 秒，恰好 180 秒允许。多 P 按整个视频总时长检查，指定短片段也不能绕过。元数据未给出可靠时长时不读取字幕、下载视频或调用转写。
- 缓存每次重新检查 @ 与当前时长配置。跳过结果只返回原因与门槛，不携带简介、字幕、画面或转写。
- `integrations.bilibili` 可配置 `maxVideoSeconds: 180`、`defaultFrameCount: 8`、`maxTextChars: 6000`。`extensions.bilibili.config` 的同名设置优先。正文预算为字符数；需要时仍可在限额内明确指定最多 16 帧。
- 固定唤醒指令的同一离线夹具从 3110 字符减至 2280 字符，减少约 26.7%。这是固定文本体积比较，不是实际计费 token 节省率；动态消息、关键词提示、工具清单和实际调用都会影响总消耗。

## 记忆与关系

在 `config.json` 配置：

```json
{
  "extensions": {
    "social-memory": { "enabled": true, "config": { "people": [] } }
  }
}
```

`people` 是额外允许建档的真实 QQ 账号列表，默认同时使用私聊白名单和管理员。群白名单不会自动授权群内所有人建档。人物身份取自宿主实际收到的消息，不按昵称或模型提供的账号猜测；撤销白名单后旧会话令牌不能继续读取。

本地数据库位于 `state/extensions/social-memory/`：`memory.db` 保存事实、画像、关系事件和待同步任务，`keyword-index.db` 保存关键词索引、版本及删除标记。均使用 SQLite WAL。正文留在本地，自动注入只带当前说话人的简短相处提示、关键词和记忆编号，限制在约 800 字符；需要正文时再用 `qq_social_memory_read`。

DSH 通过现有受限 QQ MCP 获得 `qq_social_memory_query/read/remember/forget` 和 `qq_social_relationship_event` 五个工具。这就是本次的上下游联动：项目维护持久关键词索引，上游按权限查索引、按编号取正文；没有写入全局 meow-memory 的内部 SQLite，也没有放开原生 `memory_*` 工具。缺少受控上游 CRUD 接口时，不会宣称全局原生记忆已同步。

人物共用默认五档：戒备、礼貌、熟悉、亲近、深交；每个人的亲近、熟悉、信任及边界记录独立。规则包括单次变化上限、冷却、同类重复减益、每日变化限额、迟滞和时间衰减。群聊只得到定性的相处提示，不得到私聊分数或私聊正文。档位与事件规则定义在 `lib/social-memory/src/config.js`，本轮保留该原型默认规则。

真实聊天停用原型的关键词假提取器，不新增一轮独立 LLM 请求。现有聊天智能体根据有依据的消息调用记忆/事件工具；本人明确自述才能标为确认，推测先存为待确认。关系事件证据必须是绑定消息的子串，不能直接设分；同一消息只能记一次关系变化。文字证据校验不能代替语义判断，因此关系行为效果仍需后续实际聊天观察。

事实按群/私聊范围隔离。忘记、纠正、过期、撤权及索引墓碑由本地规则控制；默认不会把历史聊天全量导入，也不会根据不在场人物的昵称拼画像。现有旧摘要保留，并限制入口文本预算。

## 升级与恢复

1. 停止桥接后，保存当前 Git 提交/标签，使用 `git bundle create repository-before.bundle --all` 备份历史、`git archive` 导出旧代码。复制 `config.json` 和重要状态到私有 `state/backups/<时间>/`，生成 SHA-256 清单；备份目录不提交 Git。
2. 已经运行的 SQLite 不能只复制单个 `.db`：先停机关闭连接，或使用 SQLite 在线备份接口；恢复时核对 `.db`、WAL 和 SHM 的一致性。新建库不迁入演示或夹具数据。
3. 升级代码并安装锁定依赖，启用插件，重启桥接。现有 DSH QQ MCP 清单需重连，新的工具才会出现；QQ 预设守卫通过原有工具前缀授权，不开放本地执行。
4. 核查插件状态、180 秒配置、MCP 工具清单和上游连接。离线测试/握手不等于真实发信、视频观看或好感度语义效果验收。

故障时可先在管理页停用 `social-memory`，停止其任务与工具。整体回退时先停桥接并再备份新增数据，在独立目录检出旧标签 `v0.3.0-rc.1`、执行 `npm ci`，接回备份的配置。保留当前发送幂等账本和聊天状态，新增记忆数据库另行保存；不要直接把整份旧状态覆盖回去而丢掉升级后的消息。原型仓库的独立标签不替代主项目备份。

不要执行 `git clean -fdx` 或清空 `state/`；它们会删除私有配置、凭据、账本和记忆。标签及备份均不可覆盖，发布使用新的版本号。

## 验证命令与边界

`npm test` 覆盖原有集成和本地记忆库、视频门槛及真实唤醒入口；`npm run test:audit` 覆盖全项目离线审计。`npm run test:mcp-servers` 进行三个 MCP 的真实 stdio 握手，`npm run release:check` 核对发布文件、版本和私有资料，`npm audit --omit=dev` 检查依赖。DSH 工具名对账使用本机实际安装模块目录，经环境变量 `DSH_INSTALL_MODULES` 指定。

测试使用临时数据库和假 QQ/DSH 传输，不向联系人发测试消息，不发布空间。生产健康检查只读取状态与工具清单；后续真实聊天的画像准确性和计费 token 节省需要实测。

本机本轮结果：`npm test` 137/137，完整离线审计 47/47 脚本，三个 MCP 真实 stdio 握手通过，启用记忆后工具数量为 60 / 1 / 2，依赖审计为 0 项已知漏洞。发布检查通过，私有配置与运行数据库未纳入提交。实际桥接已加载五个内置插件并连接 DSH；QQ 网关连接与真实聊天效果另按运行状态确认。
